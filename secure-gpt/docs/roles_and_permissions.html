SecureGPT: System Roles & Permissions

Comprehensive Specifications for Global Super Admins (Platform Owners) and Common Users

01 Introduction & Context

This specifications document outlines the authorization matrix, user segmentation, and capability levels for the SecureGPT platform.

Following our transition to a multi-tenant Enterprise DLP architecture, SecureGPT manages user identities and policies across multiple logical scopes. This document defines the ultimate control authority of the System Super Admin (representing the platform owners running SecureGPT) and contrasts it with the permissions of Common Users (which are segmented into Organization-Bound Users and Independent/Personal Users).

System Architecture Principle

Security policies inside SecureGPT follow strict scoping boundaries. Data protection logic must be tamper-proof for enterprise end-users while granting full control and diagnostics capability to the hosting system owners (System Super Admins).

02 The System Super Admin Role (Platform Owner)

The System Super Admin represents the platform operator (the team that owns and hosts the SecureGPT service). This role has comprehensive, unrestricted access across all tenants, databases, and configuration scopes.

Core Administrative Capabilities

  • Tenant & Organization Management: Full visibility and control over all customer Organizations. The Super Admin can register new tenants, suspend active organizations due to billing or abuse, upgrade billing plans (e.g., Free, Pro, Enterprise), and delete tenants.
  • Domain Constraints Administration: Customization of the system-wide domain blacklist. This controls which public domain emails (e.g., gmail.com, yahoo.com) are blocked during Organization registration.
  • Global Analytics & Observability: A centralized dashboard summarizing aggregate system health, active user counts, linked device volumes, total PII detection rate, and model execution times across all tenants (with individual details hashed for privacy).
  • Global Policy Templates: Management of default policies, custom regex patterns, and classifier weights automatically provisioned to all newly registered independent users or organizations.
  • Global Audit Log: Access to a comprehensive platform audit trail tracking administrative actions (e.g., who provisioned an organization, what system settings were changed, manual DB script execution) with audit hashes, risk levels, and Client IP tracking.

03 Common User Roles

Common users represent the customer audience using the SecureGPT extension and dashboard. Depending on their enrollment status, they fall into two mutually exclusive classifications: Independent Users and Organization Users.

Independent (Personal) Users

Users who register directly for individual data-loss protection without corporate enrollment.

  • Workspace Scoping: org_id is NULL.
  • Full Policy CRUD: Complete control over their active data-loss rules. They can define custom regex rules, modify sensitivity filters, and specify warning/blocking behaviors.
  • Personal Dashboard: Access to their individual dashboard showing metrics, logs, and linked devices.
  • Device Enrollment: Can register up to 3 personal devices (e.g., home PC, laptop, phone browser).

Organization Users (Enterprise Employees)

Users whose email domains match an Organization and have been auto-enrolled by their IT Administrator.

  • Workspace Scoping: Bound to a non-null org_id.
  • Locked Policy State: Legacy personal policies are set to is_locked_by_org = True and become read-only. No new personal policies can be created.
  • Policy Inheritance: Organization-wide policies are automatically pushed down and enforced on their browser extensions.
  • No Administrative Dashboard: Restricted access. They cannot access organization settings, member lists, audit logs, or edit global rules.

Dynamic Scoping and Policy Behavior

When an Independent User joins an Organization, their account undergoes an automatic transition pipeline designed to maintain company control:

Veto Power & Legacy Policies

Upon auto-enrollment, all existing personal policies owned by the user set is_locked_by_org = True. The common user loses all write privileges to these policies. The Organization Admin gains full control to review, edit, toggle, or delete these legacy policies from the admin control panel.
